CODE REVIEW FINDINGS — OCTOBER 19, 2026
Reviewed the current backend checkout at baseline commit 64b9191, the relevant
framework implementation, schema, routes, copied iOS handoffs and feature tests.
No live user records, production database or raw log contents were inspected.

1. Favorites and reading reports are distinct records
   app/Http/Controllers/Api/V2/FavoritesController.php writes explicit account
   favorites to user_purchase_records. Removing a favorite deletes its rows;
   these records have no periodic 90-day expiration in the checked code.
   Despite its historical name, this table represents saved/favorite membership,
   not an in-app-purchase receipt ledger. Popular catalog ordering counts saves.
   Account deletion also removes favorites and the account's activity records.

2. Reading/completion ingestion and payload are implemented
   app/Http/Controllers/Api/V2/StoryActivityController.php accepts a story ID,
   reading state, saved state, observed_at and mutation/request UUID. Strict
   validation rejects unexpected fields, including names, email, story text,
   private reactions and detailed positions. It stores latest known reader/story
   state and duplicate-request receipts, not a complete event/session history.
   Account identity comes from a verified bearer. Guest requests are supported
   by this backend using a dedicated pseudonymous UUID-derived reader key;
   there is no server-side switch that prohibits all guest reports. This is
   capability, not proof that the shipping app sends guest reports. The owner
   confirms no guest collection and signed-in reading/completion collection.
   The policy now reflects that scope, the supplied Reader measurement facts,
   account association and excluded payload categories.
   No Swift checkout was found in the reviewed project/common code locations.
   Copied October 14 iOS handoffs describe earlier local-only recording; they
   are historical evidence, not a current shipping-build audit. No iOS binary
   verification is claimed and the owner supplied the current reporting scope.

3. Deletion revokes Apple credentials and leaves limited security data
   app/Projects/Quickreads/Api/V2/AccountDeletion.php revokes retained Apple
   refresh credentials, removes the account, sessions, favorites, account
   activity/receipts, provider identity, reset records, comments, ratings and
   matching newsletter subscription. It leaves a minimal Apple subject-hash,
   scope and event-time security record to reject proofs issued before deletion.
   app/Http/Controllers/Api/V2/AppleLifecycleController.php requires explicit
   confirmation and a bearer issued within the last ten minutes. A provider
   revocation failure keeps the account for retry; it is not a successful deletion.
   No device-file or provider/email-backup erasure occurs in this routine.
   The policy now explicitly describes the limited Apple security exception.

4. The specific 90-day pruning rules exist in code
   app/Console/Commands/PruneQuickreadsV2.php deletes Apple notification/deletion
   security records older than 90 days, activity not updated within the configured
   window (90 days by default), and duplicate-request receipts older than that
   window. It separately expires short-lived Apple challenge/recovery material.
   app/Console/Kernel.php schedules pruning every five minutes. Actual removal
   requires the deployed host's scheduler to run successfully; a cutoff in code
   is not a verified maximum physical retention period. It is not a retention
   rule for all accounts, favorites, logs, email or backups. Numeric public
   retention wording remains withheld until the deployed job is checked.

5. Search, IP handling and application logging
   app/Projects/Quickreads/Api/V2/Catalog.php uses search/filter inputs to query
   the catalog. No first-party search-history table or explicit normal-path
   search-query audit logger was found. This does NOT prove queries are never
   retained: exceptions/database error messages or host/proxy logs can contain
   request details, SQL or bindings.
   routes/api/quickreads_v2.php and app/Http/Kernel.php apply request throttles.
   The installed Laravel ThrottleRequests/RateLimiter code derives a hashed
   account/IP request signature and uses cache counters with configured TTLs
   (one minute for these route limits). Expiry is not a universal log-deletion
   guarantee and does not prove physical removal from the backing cache store.
   The policy now discloses IP-based service protection without inventing logs.
   config/logging.php defaults to stack -> single -> storage/logs/laravel.log,
   with debug level and no rotation/expiry configured for that single channel.
   The optional daily channel has seven-day rotation, but it is NOT the default.
   The effective production LOG_CHANNEL and external rotation are not in code.
   app/Exceptions/Handler.php restricts application error reporting for Apple,
   activity and account-deletion endpoints to a generic message and exception
   class. This does not control web-server/proxy/CDN/provider logs or establish
   redaction for every other operation.

6. Backups, email geography and manual privacy requests
   No Quick Reads database-backup/deletion schedule, web-server access-log
   configuration, host cron installation, logrotate policy, Gandi mailbox
   location or deployment-specific provider agreement was found in this repo.
   Generic mail/environment examples do not establish live provider settings.
   Neither a mail hostname nor DNS answers establish physical processing country.
   The confirmed privacy inbox is the request route; no automated rights portal,
   export button, analytics switch or guest-deletion screen is promised.
   The owner-only quickreads:activity-forget-guest command deletes reporting
   records using a supplied installation UUID. It does not establish how users
   retrieve that UUID or prove that historical guest records exist in production.
   Apple consent-revoked notifications invalidate relevant sessions/credentials;
   ordinary logout remains separate from account deletion/consent withdrawal.
